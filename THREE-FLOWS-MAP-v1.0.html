🖼️ Lane 1 · Image posts

AUTOMATION + TEAMLIVE since Aug 25Tue + Sat · 21:00 New York · map v16
1Sunday scrape + Monday research — Apify pulls 6 tracked brands + your own account (45-day window) Sun 11 PM; at Mon 10 AM the research agent ranks by engagement rate, screens against brand-guide.md, publishes 18–25 candidates. ~55 min, four phases, critic pass on Opus.
2Visual screening — Claude looks at every candidate image against the 12-point rubric; 8–12 survive; every slide archived because IG links die within days; thin weeks topped up from earlier high scorers, never padded.
3You (or Charles) pick — Monday invite email → Selene Picks page → click individual images, up to 15 a week, ≤5 per post; first submit locks the week; overflow shelves to next week. Week of Sep 7 is picked (rows #30–35).
4Prompts → images → QA → caption, no flips — prompt runner writes one prompt per image and sets D=Ready itself; generation runs 1–4 min per row (Google's model, capacity retries); QA scores against the same rubric; caption fires the moment images finish (7-style register, brand-review pass, dashes banned).
5You approve on the review link — every post drawn as a real IG post; drop, reorder, pick cover, edit caption, reroll one slide. Approve writes Scheduled + a date. Emails every 30 min: posts ready · publish failed. This is the “weekly email link”.
6Auto-publish with shop tags — launchd pokes /publish every 15 min; slides resized, AI-provenance metadata stripped (no “AI info” label, proven), hosted, posted as a carousel, product tag on every slide from the Shopify catalog (fail-open), live URL written to col O.
7It learns — Sunday scrape reads your own posts, joins them to the row via col O → post-outcomes.csv, generation-scores.csv, prompt playbook, visual taste. The only lane with a closed loop.
Strong
  • Fully closed loop: research → pick → make → approve → post → results → next week.
  • Two human gates placed where they can answer the question (after the post exists).
  • Shoppable, no AI label, cancel-until-it-fires, review page you can use on a phone.
  • Most mature: 16 map versions, every failure so far has a fix or a documented recovery.
Weak / open
  • Server down = silently missed slots. Happened twice (Aug 26–29, Sep 1–4). The email watchdog only sees J=Hold; it cannot see a dead server.
  • Cadence drift: rows approved Aug 31 got near-daily dates, not Tue/Sat.
  • “Cooling Blanket” / “Gauze Blanket” errors a row every time one is picked (fix known, not applied).
  • Generation ERROR rows do not email you; pipeline-state.json loses entries when six rows fire together, so the dashboard under-reports.
  • Drive OAuth token expires (likely a 7-day “Testing” consent screen — unverified); dead token = generation just stops.
  • Picker v4.0.b and review v2.0 written; whether both are pasted + deployed is unconfirmed.

Strong

  • Honest about uncertainty end to end — an unclear product propagates to every downstream stage (learned the hard way from “#linenthrow”).

  • Variants turn one clip into a hook experiment; cooldowns prevent spam.
Weak / open

  • Two live captions asserted unverified material facts (“lightweight cotton weave”). Hooks reject numbers; captions do not yet reject claims. The claims file exists one lane over.
  • Trial reels are a weak caption test: watch-through decides reach, the caption rides along (you accepted this).
  • Same silent-server and dead-Drive-token risks; nothing alerts you.
  • Music path never mixed a real file; six retired synthetic clips still sit in the drop folder.
  • No notification at all: you find out a reel went out by opening Instagram.

⛓️‍💥 Where they could meet and don't — ranked

NOT BUILTnothing here was changed · your call, later
Ordered by how much weekly friction each removes, divided by how much it would take. Blue-edged = a design decision for you; orange-edged = a plain gap.
1 · One place to approve everything BIGGEST WIN
Today: web page (image), two sheet cells (edu), Instagram app (reel). The review page v2.0 already draws a calendar from both sheets and has a Queue/Calendar layout built for phones. Adding an edu section (approve words · approve look, strip shown inline) and a read-only reel feed (what went out, what's parked and why, “graduate this” reminder) would make it the hub. Google-hosted, so it opens even when the Mac is asleep. → Extends what exists; no new hosting, no new login. See “One-stop hub” below for the alternatives.
2 · One down-detector for all three lanes SAFETY
Every lane dies silently when the Mac sleeps; it has already cost the image lane two batches of missed slots. A single check that runs in Google's cloud (Apps Script time trigger → tunnel /health → email/push when it fails) covers all three at once, because they share the launcher. → One trigger, one email. The cheapest fix on this page.
3 · One inbox, one style of message GAP
Image lane mails from Apps Script; edu wants to mail from the Mac (unset); reels never mail. Routing edu and reel events through the Apps Script mailer that already works would give you one sender, one subject pattern — and the edu strip email would finally arrive without an app password. → Or drop email as the entry point entirely and make it a notification pointing at the hub (item 1).
4 · One results table LEARNING
Only image rows get outcomes. Edu posts are on the grid but never joined; trial reels are not on the grid at all, so the scrape cannot see them. A Meta insights read (permalink → likes/saves/shares/views) writing one post-outcomes table keyed by lane + row would close the loop for all three and finally test Thursday, the hooks, and the variants. → Needs the insights scope verified once. Reels: read by media id, not by scraping.
5 · One claims file BRAND RISK
claims_edu.md holds the audited truth (340 TC, 365-day guarantee, GOTS unconfirmed, OEKO-TEX at facility level). Reel captions and image captions never see it, and reels have already stated unverified material facts twice. → Point the reel caption gate and the image brand-review pass at the same file. Small.
6 · One product parser KNOWN BUG
reel_products.py reads “01. Product Photos” correctly; the image lane's lookup splits “Cooling Blanket” wrong and errors the row. Same folder, two readers. → Reuse the reel parser in the image lane. Already noted as the fix reference.
7 · One calendar that owns the days DECISION
Tue/Sat vs Thu is a convention; each publisher reads only its own sheet; reels can land the same day as a carousel; image dates already drifted daily. A shared slot allocator (or just the hub calendar refusing double-bookings) would make the week legible. → Decide first whether reels should respect carousel days at all — they reach strangers, not followers.
8 · Back-port the legibility fix SMALL
The reel overlay scores luminance and escalates the scrim; the edu renderer has no such check and pale photos are an open problem. Same Pillow, same brand. → Copy the logic across; no product change.
9 · One state file, one dashboard LATER
pipeline-state.json (image), the edu log, reels.json. The status page reads only the first. A /state that merges all three would let one dashboard say “what is running, what is waiting on me, what failed” across lanes — which is what a hub needs underneath it. → Build after item 1 decides what the hub is; the state file follows the surface, not the other way round.
Ideas I would not chase yet
Hook bank → image caption openings (voice is already shared via rotation; adding hooks risks sameness) · reel frames as edu Real Moments photos (different aspect, different purpose) · Notion as the control surface (see below).

🧭 One-stop hub — replacing “the email with a link”

FOR YOUoptions, not a build
First, what is actually unreliable. The review page itself is Google-hosted at a fixed URL that never changes; it works whether or not the Mac is awake (only live thumbnails and Mac-side actions need the tunnel). The fragile parts are: (a) the email as the entry point — it gets buried, arrives only on transitions, and edu's version never sends; (b) three surfaces instead of one; (c) nothing tells you when the machine behind them is down. A link is not the problem. Depending on the email to find the link is.

Pin the URL you already have DO TODAY

Bookmark …/exec?view=review on phone home screen and browser bar. Zero build. Email becomes a nudge, not the door.

+ instant · permanent URL · nothing to deploy

− still three surfaces · no Mac-down warning

Grow the review page into the hub RECOMMENDED

review.gs v2.0 already has Queue · Calendar · Needs-attention and reads the edu sheet. Add: edu approve-words / approve-look sections (strip shown inline), reel feed (read-only + graduate reminder), a “Mac last seen” line, push instead of email.

+ Google-hosted, opens with Mac asleep · same login as today · sheets stay the source of truth · calendar already half-built

− Apps Script limits (one router, paste-to-deploy, 6-min runs) · images via Drive thumbnails · reels need a /calendar endpoint that isn't built

Notion NOT AS THE CONTROL

Nice mobile app, but it would be a mirror: something must sync sheets → Notion and poll Notion → Mac for approvals. That is a fourth integration and a second source of truth, and it cannot draw a post as Instagram does.

+ pleasant to read · good for notes, the promo calendar, decisions log

− new sync to build and babysit · approvals lag by the poll interval · no IG-style preview · one more thing that breaks when the token expires

A page you refresh yourself PARTLY YES

Two flavours. (i) A Mac-served page through the tunnel: live, but dead exactly when you most need it. (ii) A static page on GitHub Pages fed by JSON the runners already push to the memory repo: survives the Mac being off, refreshable, no login — but read-only; approvals would still route through Apps Script or the tunnel.

+ (ii) is a good status screen and could show all three lanes

− not an approval surface on its own · public repo = careful what the JSON contains

Small cloud app (Cloud Run / VPS) LATER, IF EVER

The “proper” answer: one web app, own auth, reads the three sheets and the state, writes approvals, pings the Mac. Solves the UI half of the Mac problem, not the generation half — images and reels still render on the laptop.

+ no Apps Script limits · one codebase for all lanes

− biggest lift · new hosting, auth, secrets · the 24/7 laptop still has to exist

Cowork artifact (like the status map) NO

Snapshot only. Cannot read live sheets or take an approval. Fine for maps like this one, wrong for a control surface.

Recommendation, in order: (1) pin the URL now · (2) the cloud down-detector, because every hub is useless if you can't tell the Mac is asleep · (3) grow review.gs into the hub, edu first (its approvals are already just cells), reels read-only · (4) push notifications from the same script instead of three mail paths · (5) the merged results table, so the hub can show outcomes next to approvals. Notion stays optional for notes; not for approvals.
What I am unsure of: whether review v2.0 / picker v4.0.b are deployed right now · whether an edu post has gone end to end since Sep 9 · whether the reel publisher shares any Graph code with publish_runner or is fully separate · whether the research agent actually writes suggestions into the Post Topic sheet or that is still a manual paste · whether you want reels to respect carousel days at all. None of these change the shape above; they change the order of the first two builds.
